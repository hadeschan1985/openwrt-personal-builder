# 电视盒子型号、内核与 DTB

“电视盒子全系列”是 Kwrt `armsr/armv8` 下的 `box` 档案。普通 ARM64 EFI、原生 N1 与此打包流程各自保留，不能把一个平台的内核任意装到其他设备上。

网页提供固定型号与固定内核选择，DTB 随型号自动匹配，不接受任意 DTB、下载地址或 Shell 参数。未开启盒子打包时，仍可单独生成原生 ROOTFS；开启后，ROOTFS 作为中间输入，交付 Btrfs 的完整 `.img.gz` 磁盘文件及校验报告，不把原生 ROOTFS 冒充打包后的根文件系统。

## 固定公开资源

打包器来自 [ophub/amlogic-s9xxx-openwrt](https://github.com/ophub/amlogic-s9xxx-openwrt)，源码提交和四个辅助仓库均固定在 `configs/box-sources.json`。每次拉取后核对提交身份，型号数据库与打包脚本另核对 Git blob 身份。

内置历史基线有 209 个资源匹配档案。新增每日资源检测会检查完整型号库，只有能匹配已固定内核及真实 DTB 的条目才进入候选；缺资源的条目保留明确排除原因。最新批准数量以网页目录为准。资源匹配数不是逐台实体设备验收数，也不能直接与主设备目录相加，因为其中有重叠型号。

内核来自 [ophub/kernel](https://github.com/ophub/kernel)。每日跟进 stable 的 5.15、6.6、6.12、6.18 系列以及 rk35xx/rk3588 的 6.1、6.12 系列。候选读取已发布产物，固定版本、大小与 SHA256；解析实际 DTB 的根 compatible 属性和摘要，再绑定对应型号。每个内核和平台组合都须实际打包及回读通过。型号不兼容的内核不会出现在选项中，不将内核系列名称当作已经验证的具体版本。

## 云端流程

1. 使用所选 Kwrt 构建器解析实际软件依赖，生成包含个人首次开机设置的 ROOTFS。
2. 识别并移除作者服务器专用的 ARM64 `Image/Build` 钩子，保留正常 ROOTFS 生成。
3. 将五个固定提交检出的资源复制给打包器，预置已核对 SHA256 的内核；禁用 latest 查询与运行中滚动克隆。
4. 删除原打包器在主机中 `source` 固件 `/etc/openwrt_release` 的步骤，改用固定发行身份。个人初始化 Shell 与 IPK 内容仅写入设备镜像，构建主机不执行这些内容。
5. 仅在隔离的 Linux GitHub runner 中创建本轮镜像文件和相应 loop 设备；不会访问个人电脑物理盘或家庭网络。
6. 对压缩后的实际成品解压、只读回读，核对型号 DTB 的 SHA256/compatible、引导配置、内核模块 vermagic 和个人设置脚本摘要。失败停止交付。

回读调试发现当前 GitHub 内核已移除旧的独立 `nologreplay` 挂载参数，现使用 `ro,rescue=nologreplay`。这与 [Btrfs 内核变更记录](https://btrfs.readthedocs.io/en/latest/Kernel-by-version.html) 中的替代写法一致，保持只读和禁止日志回放。

## 内核驱动与验证边界

盒子使用所选内核自带的完整模块集，不能混装 Kwrt 原生内核的 `kmod-*`。网页和构建端均拦截显式混装，以及原生 USB 网卡、USB 无线、WWAN 驱动开关。打包过程用匹配模块替换原模块；后续驱动更新也必须与盒子内核配套。

用户空间软件仍按所选 Kwrt 源解析依赖。包安装成功、文件校验成功不代表具体芯片、无线射频、网卡、代理线路或实体开机已经验证。每次批准保存不可变目录；网页有新版提示，使用者点击后切换。恢复历史配置时读取其原目录并检查内容身份，不能偷偷换新内核。

盒子定时任务于 UTC+8 05:43 计划运行，GitHub 可能延迟。源码或内核无变化且验证规则相同时复用证据；资源、规则变化时重新验收。发布只写批准数据，并发构建记录会保留；相关构建代码变化会拒绝本次批准。固件仍由使用者另外提交构建。历史基线证据见 [RELEASE-12.md](RELEASE-12.md)，新资源的具体证据见网页批准记录。
