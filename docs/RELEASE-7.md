# 交付完善版：正式构建与私有收藏

## 正式 / 实验模式

新选的 x86/64 设备默认使用正式模式。旧模板、旧 JSON、默认手动示例保留为实验模式，不会未经确认自动改变旧配置。

正式模式要求私有构建仓库、HTTPS，以及仓库 Secret `ROUTER_PASSWORD`（至少 12 个字符）。密码由本人在 GitHub 仓库 Settings → Secrets and variables → Actions 中设置；不发到聊天，也不写进网页配置。

每次正式构建后，在隔离 QEMU 中启动本次生成的全部 EFI、Legacy、VMDK 磁盘，测试后台密码、HTTPS 登录、已认证 RPC、主机名、管理 IP、DHCP 设置、指定安装/移除的包。镜像不注入测试密钥，不修改交付文件；虚拟机使用临时快照、只允许回环转发，不访问外网或宿主机文件。

若选中 Aria2 / SmartDNS / Samba，执行本地下载、域名解析或临时共享读写检查；Xray 和 sing-box 执行最小配置语法检查。不是用户真实代理节点、运营商线路或 USB/无线实物测试。首次启动脚本若使后台无法访问，正式构建会失败，不会自动绕过门槛。

目前正式验收只支持 x86/64、EFI 或 Legacy 磁盘、eth0–eth7、/8–/30 管理网段。仅 ROOTFS、其他架构和特殊网络配置须明确使用实验模式。正式虚拟机验收不代表实体设备安全刷机，不会自动刷新任何设备。

## 下载清单与配置重用

新构建按 EFI、Legacy、VMDK、ROOTFS 分包，不必下载所有格式。报告另存；旧构建的完整 ZIP 仍可下载。

构建完成后，独立的低风险记录任务把本次配置引用、源代码提交、各文件大小/SHA256、验收状态写入私有仓库 `records/任务编号.json`。记录任务不会执行第三方构建器或初始化 Shell。真实密码值不进入记录；自订脚本和文件包路径可能包含私人内容，因此记录绝不复制到公开网页仓库。

连接网页后可查看逐项清单、翻阅历史、点击“用此配置重新填写”。该按钮不会立即开始构建；原来选择的本机文件不会自动再次上传。正在执行或失败的新构建不会覆盖首页最近成功的个人结果；内部验收任务会标明，并排除在首页默认结果之外。

## 我的私有收藏

普通 Actions 下载包保留 7 天。希望保留的成功固件，可以手动点击“收藏到私有仓库”。收藏工作流校验下载 ZIP、逐文件大小和 SHA256，再上传到同一个私有仓库的 Release；需 GitHub 登录才能下载，不会公开到 Pages。

安全限制：最多 5 个版本、每次最多 1.5 GiB。满额或失败时显示原因，不自动删除旧版，也不自动重复提交。归档草稿会占一个名额，重跑同一任务可以补齐相同文件，但不覆盖内容不同的已有文件。完成的同一版本再次请求是幂等操作。

收藏不受普通产物 7 天过期影响，但不是永久保存承诺、系统分区回滚或整个软件源快照。平台仍依赖 GitHub 账户、策略及上游可用性。必要时自行另存重要固件与配置；本项目不自动删除任何收藏。

无需新建长期访问令牌、扩大现有网页令牌权限、使用 VPS 或启用付费服务。收藏任务只在运行时使用仓库自己的短期令牌。
