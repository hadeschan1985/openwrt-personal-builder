# 个人工作台使用方法

本文是当前使用入口。历史报告中的设备范围、测试数量和旧链接以本文及 [当前交付范围](DELIVERY.md) 为准。

[打开工作台](https://hadeschan1985.github.io/openwrt-personal-builder/?v=20261028-1) · [私有构建记录](https://github.com/hadeschan1985/openwrt-personal-builds/actions/workflows/build.yml)

## 选择设备和软件

1. 在“固件版本”选择 Kwrt 全设备固定构建器，可搜索原站当前目录中的 865 个设备档案、24 个平台。官方 OpenWrt 目录单独保留，不混用软件源。
2. 输入型号，也支持红米、小米、华硕、网件、斐讯、树莓派等常用中文品牌和型号组合。
3. 选择出厂包移除、常用软件、代理插件、主题和网络设置。可用包按设备架构列出，灰色表示当前索引缺包；实际构建还会检查依赖和冲突。
4. 查看设备自己的固件格式。默认优先 sysupgrade；factory、SD 卡、EMMC 等格式只在该设备提供时出现。需要多个格式可多选，下载仍逐个分开。

目录收录不表示本项目测试过这台实体设备。连接私有仓库后可选择最新“多设备自动更新”版本，或点“此设备使用最新验收版本”，保留现有软件和网络设置。N1 和玩客云修复在对应的新验收版本启用；旧固定版本保留原状态。Wavlink WL-WN573HX3 的 Kwrt 档案只有 ROOTFS，可点击“改用官方源生成完整升级镜像”，切换至官方 `WN573HX3-sysupgrade` 格式；切换后重新检查软件列表，不能混用两家的软件源。切勿只凭相似型号名称选择固件。

## 电视盒子型号与内核

在 Kwrt 版本中搜索“电视盒子”，选择“电视盒子全系列”。到“映像与文件”开启“按盒子型号打包完整磁盘镜像”，再选择具体型号和内核。DTB 自动匹配，不需要自己填写。内置历史基线保留；连接私有仓库后可载入新批准目录，点击应用后才切换，只显示该型号支持的已固定版本。

输出是独立的 Btrfs `.img.gz` 磁盘文件；ROOTFS 仅作为打包输入，不是另一个冒充完整固件的下载包。关闭型号打包可继续单独生成原生 ROOTFS。盒子使用所选内核的模块集，不能同时选择原生 OpenWrt 的 USB/WWAN 驱动开关或 `kmod-*`。用户空间软件仍按 Kwrt 源选择。

新批准目录要求每个内核及平台组合实际打包与回读。其他具体型号没有因此自动获得实体开机证明。原生 N1 的 sysupgrade 与这里的 N1 磁盘镜像属于不同安装方式。没有设备恢复说明时不要混用。详细范围见 [盒子说明](BOX-COMPATIBILITY.md)。

## 后台账号与验收模式

- 用户名固定 root；新配置的临时默认密码按你的要求设为 root。
- “后台密码来源”也可改为“我的 ROUTER_PASSWORD”，使用私有仓库 Secret；该模式要求至少 12 字符，最多 128 UTF-8 字节，不含冒号、换行或空字符。
- 原来的自动填写草稿会补上临时 root 默认值；已明确选择自定义密码的草稿保持原选择。导入旧记录不会偷偷改变其密码语义。
- x86 启动验收：本次选定的 EFI、Legacy、两种 VMDK 都须实际在隔离虚拟机启动并验证登录。
- 设备编译校验：用于其他型号，检查依赖、请求的软件、实际文件和 SHA256，识别压缩包与 OpenWrt 固件尾部；不声称设备已通过实机开机测试。
- 实验模式不执行启动验收。涉及正式交付或设备校验的配置要求私有仓库、密码和 HTTPS。

root 是临时默认密码，可首次登录后修改。项目不会替你改 GitHub Secrets，也不会自动刷机或修改家庭网络。

## 提交构建

已连接网页时，点击“构建新固件”直接提交；同一请求等待期间不会重复提交。

构建逐个运行，多个已提交请求进入 GitHub 有界队列，不因后来的请求替换前一个等待任务。队列最多容纳 100 个等待任务；满载、账号配额或服务故障仍可能使请求失败，页面会显示真实任务状态。

不输入网页令牌时，点击“查看 / 导出配置”，复制配置，再打开 GitHub 的 Run workflow，把配置粘贴到 config_json 后运行。不要留空，否则使用仓库示例配置。

自订文件包支持 ZIP / TAR.GZ / TGZ / 7Z，最大 12 MiB。按根目录结构覆盖文件；Kwrt 自订 IPK 必须匹配当前设备架构，包内安装脚本在设备首次启动时运行。核心包和内核模块仍从相同构建器的软件源选择。

PPPoE 可引用 PPPOE_USERNAME、PPPOE_PASSWORD；Wi-Fi 可引用 WIFI_PASSWORD。密码由本人在私有仓库设置，不要发送到聊天。

## 首页下载和本机校验

连接构建仓库后，首页“最近编译结果”显示最近成功任务。手动在 GitHub 运行的正常构建也会显示。首页结果与当前尚未提交的表单分开。

x86 的 EFI、Legacy、EFI VMDK、Legacy VMDK 分别下载；其他型号也逐个文件下载。GitHub 普通产物外面有一层 ZIP，每个固件 ZIP 仅含一个映像。日志与报告独立提供，无需下载所有格式。

页面显示大小、SHA256 和到期时间，可选择已经下载的 ZIP 或映像在本机校验，带进度和停止操作。文件不上传。旧构建 #5 已拆成私有 Release 中的四个单独文件；原始下载包保留。

普通产物保留七天。需要长期保留时，手动“收藏到私有仓库”；最多五版，项目不自动删除旧收藏。私有产物下载需登录 GitHub。

成功的新构建会另行归档实际构建器、软件包及对应打包资源。记录出现“用归档软件离线重建”后，可不依赖上游软件源重新生成原配置。它不能顺便修改软件或设置；需要修改时使用“用此配置重新填写”。较早未归档的记录没有该按钮。输入快照与成品收藏用途不同，容量上限、Secret 引用及可重建边界见 [归档说明](REBUILD.md)。

## 网页授权与异常

ChatGPT 的仓库连接不自动传给 Pages 网页。网页用自己的短期令牌，仅授权私有构建仓库，Actions 读写；上传文件或收藏还需 Contents 读写。令牌不进入网址、源码、模板、导出配置或浏览器存储。

刷新、关闭或点击断开会清除当前页面授权，GitHub 已受理的任务和定时检查继续运行。重新连接后读取原有记录，无需重新编译。

授权到期或权限不足时停止轮询并提示重连。遇到请求限流，按 GitHub 给出的恢复时间等待，多次限流进一步暂停。历史结果保留；网络超时先检查 GitHub 是否已经收到请求，系统不会自动重复提交。

## 上游更新

每天 04:23（北京时间 / 新加坡时间，GitHub 可能延迟）检查官方稳定版及 Kwrt 当前系列 x86/64；通过构建、引导和登录回归后才批准。每天 05:07 检查 Kwrt 多型号，每天 05:43 检查盒子源码、内核和 DTB；发生变化的部分实际编译或打包、校验后才批准。连接网页会载入已批准版本，不覆盖正在编辑的配置。新发行系列须重新通过全部相关验证；未知结构保留旧版。

无变化时复用同一构建器、设备资料和验证规则对应的证据，不重复编译。历史配置会读取其原验收版本，不偷偷改用新版。网页逐目标平台读取资料并校验 SHA256；错误时保留原配置、阻止提交。

Kwrt 当前公开目录合计 865 档案，x86 与非 x86 使用各自验收版本。代表型号通过不等于同平台每个型号都编译过。每周逐型号检查另保存公开合成配置的结果；只有与当前构建规则和平台资料一致的报告，页面才显示该型号单独通过或最近失败。没有实体设备时，本项目不声称实机开机、无线、USB/WWAN 或 ESXi 宿主机验收已完成。

滚动源再次变化时，尚未重新批准的旧版本会暂停正常新构建；已有输入快照可用断网重建。原有固件下载按原期限保留。盒子更新也须验收后批准，历史配置保留原内核；项目不会自动刷机。

最新测试与已知问题见 [本轮报告](RELEASE-12.md)。
