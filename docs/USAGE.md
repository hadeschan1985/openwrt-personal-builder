# 个人工作台使用方法

## 正式模式、逐项下载与私有收藏

新选 x86/64 默认正式模式，要求私有仓库、HTTPS，以及本人在仓库设置的 `ROUTER_PASSWORD`（至少 12 字符）。每次实际映像须通过隔离启动验收才交付；其他架构、特殊配置和旧模板明确标为实验模式。新构建按格式下载、显示逐文件 SHA256、可重用配置和手动收藏到私有仓库。普通产物七天到期，收藏最多五版且不会自动删除。完整说明见 [DELIVERY.md](DELIVERY.md)。

## 自动跟进上游

主页已增加上游状态区。每天自动检查官方稳定版与 Kwrt 25.12 x86/64，发现变化先做构建和六种引导/后台登录回归，通过后加入版本列表；不替你更改当前配置、不自动刷机。连接私有仓库后会自动载入批准结果；关闭网页不影响定时检查。详细范围、权限与配额说明见 [UPSTREAM.md](UPSTREAM.md)。

## 首页直接查看编译结果

首页顶部“最近编译结果”显示仓库最近成功的任务、完成时间、ZIP 下载包、大小、SHA256 和到期时间。连接后自动更新，手动在 GitHub 运行的任务也会显示，不需要重新编译。

未连接时点击“连接查看结果”。登录 GitHub 本站不代表已授权 Pages 网页；网页刷新/关闭会清除内存中的令牌，重新连接后就能读取原有结果。不会为了显示结果而公开你的私有固件，也不会持久保存令牌。模板的“下次自动填写”不是保持 GitHub 登录。

新任务正在执行或失败时，首页仍保留最近成功的下载包；任务成功但产物被清理/到期时会明确提示，不提供失效下载。首页结果和下面尚未提交的表单配置相互独立。旧任务下载完整 ZIP；新任务按 EFI/Legacy/VMDK/ROOTFS 分包，显示逐项清单和 SHA256。内部验收任务在历史中标明，不替换首页的个人结果。

## 不输入网页访问令牌的方式

1. 在网页选择设备、明确的固件版本和需要的软件包。
2. 设置后台 IP、主机名、主路由/旁路由、输出格式等。只有当前源中确实存在的软件可选；灰色插件不是已实现的功能。
3. 点“构建新固件”或“查看 / 导出配置”，点“① 复制构建配置”。
4. 点弹窗内“② 打开 GitHub 开始构建”，在内部浏览器保持 GitHub 登录。
5. 点 Run workflow，把 JSON 粘贴到 config_json，再点 Run workflow。config_path 保持默认；config_json 留空时将使用示例配置，而不是网页选择。
6. 在构建记录中打开对应任务。完成后，从 Artifacts 下载 firmware 压缩包，解压后核对 SHA256SUMS。

这条路径不需要 VPS，不需要会员，也不需要向网页或聊天发送 GitHub 密码和访问令牌。

## 网页直接构建

在“GitHub 连接”输入仅授权私有构建仓库的细粒度令牌，权限为 Actions 读写、Contents 读写和必需的 Metadata 只读。连接后可直接提交、上传文件包和查看历史。

令牌只保存在当前网页内存，不写入源码、导出的配置或浏览器持久存储；刷新或关闭页面会断开连接。当前授权有效期 30 天，过期后需重新授权。不要把令牌发到聊天，GitHub 密码只在 GitHub 本站输入。

连接后可点右上角“断开授权”：清除本页授权和私有结果显示，中止本页查询；未提交配置与当前文件选择保留。不撤销账号中的令牌，不取消 GitHub 已受理的任务。若断开时正在提交，重连后先检查记录，避免重复提交。关闭连接弹窗也会清空未使用的令牌输入。

## 完整软件组合

在“软件与插件”展开“一键加入完整软件组合”。官方提供家用网络、文件与下载；Kwrt 提供 PassWall2 双核心、HomeProxy 与常用工具。组合只添加软件，不覆盖网络、密码引用、脚本或文件设置；再次点选不会重复添加。

PassWall2 双核心明确加入 xray-core、sing-box 与证书包，HomeProxy 明确加入 sing-box。二者要求 nftables。其他插件的核心和运行方式依上游而定；OpenClash 仍需检查核心与配置，平台不会自动获取未知二进制。多个 DNS/代理的提示是运行冲突提醒，不代表平台会替你配置节点或端口。

## 自动进度与防重复提交

网页直接提交后会分配请求编号，等待 GitHub 登记期间及运行期间禁用重复提交。构建记录自动更新，展开任务可见中文步骤；切换到后台时暂停查询，回到页面后继续。

若提交超时，先检查记录，不会自动重试构建。超过两分钟仍无法登记且没有发现执行中的对应任务时，才显示“已检查 GitHub 记录，解除本页等待”。此按钮只解除本页保护，不会取消 GitHub 上的任务；重新提交前确认没有重复任务。请求编号保存在本标签页会话中，不包含配置或令牌。

构建时先调用对应 ImageBuilder 的实际包管理器解析依赖；缺包、依赖冲突、被依赖重新加入的移除包会在生成映像前停止。这个过程需要下载构建器和软件，因此不是网页上的瞬时离线检查。通过预检仍可能在后续生成映像时遇到空间、上游变动等问题。

## 密码与私人文件

- 网页中的“设置后台密码”使用私有构建仓库的 ROUTER_PASSWORD Secret；正式模式至少 12 字符、最多 128 UTF-8 字节，不能有冒号或换行。
- 新构建只把后台密码的随机盐哈希集成到平台初始化脚本，不再集成明文；哈希也属于私人内容，固件仍须私有保存。本人脚本、PPPoE/Wi-Fi 和文件包另按私人内容处理。
- PPPoE 使用 PPPOE_USERNAME、PPPOE_PASSWORD；Wi-Fi 使用 WIFI_PASSWORD。Secrets 由本人在仓库设置中填写，不发送到聊天。
- 填写 Wi-Fi 名称时必须同时引用 Wi-Fi 密码；不创建开放热点。
- 未启用后台密码的示例配置仅供流程验证。实际联网前应设置可靠密码。
- 初始 Shell 和文件包会进入固件。使用 Secrets 隐藏日志不等于固件内没有私人信息，产物不要公开转发。
- 文件包支持 ZIP、TAR.GZ、TGZ、7Z；不接受路径穿越、链接、加密文件包或超限解包。
- Kwrt 支持兼容的 IPK：先集成依赖，在路由器首次开机安装本地包，不在构建主机执行自订包脚本。只使用自己信任的文件包；内核模块、核心包和 APK 应从所选构建环境的软件源选择。自订 IPK 的最终安装成功须以开机后的实际状态为准。

## 日志、下载与保留期限

构建失败时先看任务红色步骤和失败日志，不要刷入残缺产物。正式模式包含本次磁盘的隔离启动和后台验收，实验模式不包含；两种模式都仍须验证实体设备与网口映射。不自动写盘、刷机或更改现有路由器。

当前成功产物保留 7 天、失败日志产物保留 3 天。需要保留时可手动私有收藏（最多五版、每版 1.5 GiB），或另存到自己的磁盘。网页只是静态界面；关闭页面不会中断 GitHub 已接受的构建。

新 x86 构建将 EFI、Legacy、EFI VMDK、Legacy VMDK 分成四个独立下载，每包只有一个映像；ROOTFS 与报告另列。按你的设备和启动方式选一项即可，不必下载其余格式。ARM 等其他平台的旧下载方式保留，不冒充已完成逐文件适配。

旧总包可点击“生成单文件下载 / 私有收藏”：GitHub 核对 ZIP、构建摘要与逐文件 SHA256 后，在私有收藏保存每个原始文件，不重新编译。完成后首页直接显示“下载这一文件”，总包收在“原始构建下载包（备用）”；日志与校验清单另外折叠。原有固件、收藏和总包不会自动删除。旧包缺少可靠清单、内容不符、到期或超过上限时会停止；已完成的收藏可重复打开。

点“校验本机 ZIP”核对原始下载包，或在逐文件清单 / 私有收藏点“校验此文件”“校验本机文件”。窗口显示目标文件、大小、SHA256、进度及“停止校验”。支持最大 4 GiB，在独立后台线程每次最多读取 1 MiB，不整体载入大文件；不是总内存只占 1 MiB。选错大小会先拒绝，同大小内容不符会报错；文件不会上传。关闭校验窗口、断开授权或切换仓库会停止校验并清理当前文件选择，已选构建文件包不受影响。通过结果仅保存在当前页面内存，断开或刷新后清除。

ZIP 下载包的校验值和解压后固件的校验值不同：下载包对照网页显示的 GitHub SHA256；具体固件对照包内 SHA256SUMS。校验通过仅说明内容完整，不代表已通过实体刷机或线路测试。构建摘要包含依赖预检结果、构建器 SHA256、代码版本和配置指纹，便于追溯；第三方滚动软件源尚未完整锁定，不能保证未来逐字节重现。

私有仓库构建使用账号现有 Actions 配额。项目未启用付费套餐、额外付费 runner 或自动充值；不要将个人自用理解为无限算力或永久云端储存。

## 选择官方还是 Kwrt

官方版本覆盖更多设备；需要 PassWall、OpenClash、iStoreX、路由狗或更多主题时，选择 Kwrt x86/64 固定版本。两者的软件源、包管理器和内核模块不能混用。

代理插件安装完成不等于线路已连通：核心程序是否包含取决于上游包的依赖；节点、订阅和运行策略需要自行配置。不要同时启用多套会争用 DNS、端口或路由规则的代理。项目不会偷偷内置测试节点。

默认主页模式中的自动/概览/面板对应原站选项；NAS/iStoreX/路由狗主页需要先勾选对应组件。Bootstrap、Argon 的浅色/深色在“默认主题”中选择。

去外链仅隐藏发行方推广链接，保留文字、开源许可和源码入口。ROOTFS 容器不包含独立内核；VMDK 的实体 ESXi 环境需要另行验证。

电视盒、任意内核/DTB/EMMC 专用打包未接入。当前不是对原站私有后端的复制，支持与限制均以页面及验收记录为准。
