# 归档软件与离线重建

成功构建完成后，私有仓库会保存该次使用的原始 ImageBuilder、软件包文件、项目构建代码和对应打包资源。盒子另保存固定源码与内核，玩客云另保存作者打包器与引导模板。每份文件有大小和 SHA256，清单与原构建记录绑定。

首页或历史记录中的“用归档软件离线重建”使用原配置提交新任务。传输阶段只核对并恢复归档；实际编译阶段没有外网、没有 GitHub 令牌，只保留本机回环通信。OpenWrt 的 [fakeroot 使用 TCP 进程通信](https://git.openwrt.org/openwrt/openwrt/tree/tools/fakeroot/Makefile?h=v25.12.6)，不能把回环接口一同关闭。每次重建先验证只有 lo 接口、没有外部地址或路由、本机 TCP 可用而外网不可达，报告随构建文件保存。旧代码按原提交恢复，不能趁重建修改软件、网络设置或文件内容。需要调整时使用“用此配置重新填写”，提交一次新的正常构建。

离线重建会核对实际安装软件及版本清单。不同即停止交付。它不承诺映像逐字节一致：打包时间、随机字段与当前引用的 Secret 值可能不同。Secret 的值、进程环境和生成后的根文件系统不进入输入归档；使用自定义密码时仍需私有仓库保留对应 Secret。用户主动上传的覆盖文件包与初始化脚本沿用原配置，仍保存在私有范围。

构建输入保存在私有 Release `rebuild-inputs-v1`，按内容摘要命名，已存在的文件不覆盖、不自动删除。单文件最多 1.5 GiB，输入总量最多 3 GiB，整个输入仓库暂设 10 GiB 上限；达到上限会明确失败并保留旧资料。流水线临时传输包保留一天，普通固件下载仍保留七天。长期保存成品仍使用独立的“收藏到私有仓库”。

相同软件包内容采用固定归档顺序、时间和权限，不因下载时间或 runner 文件属主不同而重复保存一份大型软件包文件。不同字节仍有不同摘要；不会把软件包名称相同当作内容相同。

较早构建只有配置与校验记录，不会凭空补出当时的软件包；这些记录没有离线重建按钮。已有输入归档可以抵御上游删除软件包、滚动覆盖构建器的情况。GitHub 服务、Linux runner 及主机工具仍是外部依赖，并非永久运行环境归档。固件来源软件的许可证及上游源码链接继续保留。
