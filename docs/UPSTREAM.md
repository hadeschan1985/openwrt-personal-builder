# 自动跟进上游

当前更新范围：自动测试并批准覆盖官方与 Kwrt x86/64。新增其他平台使用固定构建器和设备索引指纹，变化时暂停相应构建；全平台自动批准尚未实现。2026-10-26 至 27 的实际更新回归通过，任务 40337451276，详见 [RELEASE-10.md](RELEASE-10.md)。

## 日常使用

主页的“自动跟进上游”显示最新检查、失败状态与已批准版本。连接自己的私有构建仓库后，网页自动读取批准记录并添加固件版本。无需 VPS、会员、新的长期令牌或跨仓库写入授权。

每天计划于 04:23（北京时间 / 新加坡时间，UTC+8）运行。GitHub 调度可能延迟，不是准点服务。关闭网页不影响检查；网页会在已连接、前台显示时约每五分钟同步一次，也可点“刷新状态”。网页会话令牌到期只影响网页连接，不影响 GitHub 定时任务。

新版本加入选项，不自动替你选择，不修改当前软件包、网络、密码引用、初始化脚本或待上传文件。刷新整个网页仍需重新连接私有仓库；令牌不会持久保存。

## 自动范围

- OpenWrt 最新正式稳定版的 Generic x86/64。
- Kwrt 25.12 的 x86/64 ImageBuilder：构建器 SHA256、内核目录和七组软件包索引。
- 软件源索引内容变化，即使包名未变，也触发验证。
- 官方 APK 与 Kwrt IPK 分开处理，不混用。

这不是把上游 Git 仓库的任意代码合并到本项目，更不会自动修改网站业务代码。项目使用上游预编译 ImageBuilder，并非每次从全部源码编译系统。其他设备仍使用交付时的官方目录；本自动流程不代表其他架构经过开机测试。Kwrt 跳到其他发行系列时安全停止，需做兼容适配。

## 批准流程

1. 私有仓库 `upstream.yml` 检测版本、元数据和索引指纹；未变化时跳过昂贵构建。
2. 有变化时，用只读权限分别生成官方/Kwrt 临时测试固件。只使用随机 QA 密码和密钥，不读取用户的路由器 Secrets。
3. 两个来源各测试 EFI、Legacy、VMDK：开机、首次启动脚本、文件覆盖、网络配置、主题、root 密码、LuCI HTTPS 登录与 RPC；Kwrt 还覆盖 PassWall、Argon、NAS 和自订 IPK 的设备端安装。
4. 测试后重新读取上游，若检查期间软件源变动则拒绝批准。
5. 独立发布任务核对同一次运行的完整报告，原子提交 `configs/builders.json` 与 `updates/approved.json`；保留其他文件，不写工作流，不强制覆盖分支。检测期间若用户另有提交，本轮停止，下一次检查重试。
6. 网页经现有私有仓库授权读取批准资料，只在内存合并，不把私人固件、配置或令牌发布到 Pages。

正常的网页/手动固件构建，在构建前和构建后都会复查当前已批准版本的软件源指纹。如果滚动源再次变动，本次构建失败且不上传固件，等待新一轮自动测试。历史版本与其他架构明确不属于该自动批准覆盖范围。正常依赖预检和镜像 SHA256 校验继续执行。

## 安全、费用与限制

- 不自动刷机、改家庭网络、开启付费 runner 或自动充值。
- 使用账号现有私有 Actions 分钟与存储配额，不承诺无限免费。无变化只做索引检查；有变化最多并行两个测试任务，每个限制 45 分钟；报告保留七天，失败诊断三天，不保存 QA 固件、密钥或密码。
- 只有独立批准任务使用该仓库短期 `GITHUB_TOKEN` 的 Contents 写权限。构建上游二进制的任务保持只读，不给它发布权限；未扩大网页令牌或 Connector 授权范围。
- 更新失败时主页标明失败并保留上次批准记录。原有可下载固件仍受 Artifacts 到期限制；保留批准记录不等于上游永久保留旧构建器或软件包。
- SHA256 可发现下载损坏或字节变化，不是对第三方供应链安全的保证。未建立完整软件源归档，不能承诺长期逐字节复现，也无法完全排除两次检查之间短暂变化的竞态。
- 这六种引导回归不是所有软件组合、全部实体设备、USB/WWAN 硬件或真实代理线路的测试。
- GitHub 自身权限、配额不足或调度故障仍可中断任务。查看主页链接中的红色步骤和保留报告；不会通过改变账户收费或削弱权限自动绕过限制。

维护者可在私有仓库 Actions → Automatically follow tested upstream → Run workflow 手动复检。暂停自动跟进可禁用该工作流；历史批准和已生成产物不会因此删除。
