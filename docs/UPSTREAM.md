# 自动跟进上游

更新覆盖官方稳定版、Kwrt x86/64 与原站公开的其他平台，并新增盒子源码、内核和 DTB 的独立验收流程。当前真实通过记录与待验收项见本轮发布报告；历史证据保留在 [RELEASE-12.md](RELEASE-12.md)。

## 日常使用

主页的“自动跟进上游”显示最新检查、失败状态与已批准版本。连接自己的私有构建仓库后，网页自动读取批准记录并添加固件版本。无需 VPS、会员、新的长期令牌或跨仓库写入授权。

x86 每天计划于 04:23，多型号每天 05:07，盒子每天 05:43（北京时间 / 新加坡时间，UTC+8）运行。GitHub 调度可能延迟，不是准点服务。关闭网页不影响检查；网页会在已连接、前台显示时约每五分钟同步一次，也可点“刷新状态”。网页会话令牌到期只影响网页连接，不影响 GitHub 定时任务。

新版本加入选项，不自动替你选择，不修改当前软件包、网络、密码引用、初始化脚本或待上传文件。刷新整个网页仍需重新连接私有仓库；令牌不会持久保存。

## 自动范围

- OpenWrt 最新正式稳定版的 Generic x86/64。
- Kwrt 当前发行系列的 x86/64 ImageBuilder：构建器 SHA256、内核目录和七组软件包索引。
- 软件源索引内容变化，即使包名未变，也触发验证。
- 官方 APK 与 Kwrt IPK 分开处理，不混用。
- Kwrt 非 x86：完整型号集合、各目标 ImageBuilder 校验值、内核和设备/软件索引指纹；还固定本项目验证规则的指纹。

项目跟进上游预编译 ImageBuilder 与软件资料，不把上游 Git 仓库的任意代码合并到网站，也不是每次从全部源码重编译系统。官方非 x86 目录保持独立。Kwrt 新发行系列会生成独立候选，构建器、软件源及内核必须属于同一系列并通过实际验收；未知资料结构或不兼容改动保留原版本。多型号代表编译不代表实体开机。

## x86 批准流程

1. 私有仓库 `upstream.yml` 检测版本、元数据和索引指纹；未变化时跳过昂贵构建。
2. 有变化时，用只读权限分别生成官方/Kwrt 临时测试固件。只使用随机 QA 密码和密钥，不读取用户的路由器 Secrets。
3. 两个来源各测试 EFI、Legacy、VMDK：开机、首次启动脚本、文件覆盖、网络配置、主题、root 密码、LuCI HTTPS 登录与 RPC；Kwrt 还覆盖 PassWall、Argon、NAS 和自订 IPK 的设备端安装。
4. 测试后重新读取上游，若检查期间软件源变动则拒绝批准。
5. 独立发布任务核对同一次运行的完整报告，原子提交 `configs/builders.json` 与 `updates/approved.json`；保留其他文件，不写工作流，不强制覆盖分支。并发记录或无关页面更新可以保留；逐个核对当前 Git tree 中的相关策略文件字节，相关构建代码变化时拒绝批准。提交冲突仅有限重试。
6. 网页经现有私有仓库授权读取批准资料，只在内存合并，不把私人固件、配置或令牌发布到 Pages。

正常的网页/手动固件构建，在构建前和构建后复查已固定的软件源及构建器指纹。如果滚动源再次变动，本次构建失败且不上传固件，等待新一轮自动测试。历史批准记录不等于永久归档旧软件源。依赖预检、请求包清单和文件 SHA256 检查始终执行。已有输入快照的历史记录可另走断网重建，不访问滚动上游；实际安装软件及版本必须与原清单一致。

## 多型号批准流程

1. 私有仓库 `device-upstream.yml` 比对原站完整型号集合；不会因读取失败而悄悄丢弃型号。
2. 对比每个平台与验证规则的指纹。无变化且证据有效时复用；有变化或缺少有效证据的平台才编译。
3. 只读任务以临时 root/root、HTTPS 和不含私人文件的配置编译一个代表型号，检查实际依赖、请求包清单、固件容器及 SHA256。既不读取用户 Secrets，也不保存 QA 固件为交付下载。
4. 各平台测试后重新读取上游；独立批准任务再次检查整个集合。任一活动平台缺少有效证据，或上游中途变动，都保留原版本。
5. 批准任务只校验 JSON 并写入数据，不执行 ImageBuilder 或固件。`updates/device-builders.json` 累积固定构建器，`updates/devices-approved.json` 指向最新验收目录；历史目录及按 SHA256 命名的元数据保留。并发的记录/更新提交会被保留；代码发生变化时拒绝批准。提交不强制覆盖分支。
6. 网页读取小型目录，选择平台时才读取该平台资料，并对原始 UTF-8 字节检查 SHA256。历史配置从其历史目录恢复；切换到新版由使用者点击，保留软件、网络和文件选择。

当前目录有 864 个非 x86 档案、23 个非 x86 平台；x86 单独选择其版本，总计与原站 865 个 Kwrt 档案对应。具体批准版本和暂停平台以网页读取的批准记录为准。页面明确区分当前型号通过测试、同平台代表型号通过测试及实体硬件未测。公开仓库每周运行逐型号合成配置编译，详情见 [覆盖说明](PROFILE-COVERAGE.md)。

## 盒子批准流程

每日固定五个公开源码仓库的提交，读取已发布内核的大小、SHA256 和真实 DTB，生成型号/内核匹配候选。每个内核及平台组合实际生成 Btrfs 磁盘文件，再只读回读 DTB、引导配置、模块版本和个人设置。全部预定组合通过后，独立发布任务保存不可变目录与最新指针；不发布使用者固件，不自动刷机。资源缺失的型号继续排除。详情见 [盒子说明](BOX-COMPATIBILITY.md)。

N1 的新版本仅恢复固定 iStoreOS 源码所定义的校准链接，并检查链接及实际数据文件；没有猜测无线参数。依据见 [N1-COMPATIBILITY.md](N1-COMPATIBILITY.md)。玩客云已找回与原公布 SHA256 完全一致的作者构建器，保留于私有来源缓存；正常与归档重建均继续核对原摘要。当前下载站的替换文件不会冒充原始构建器。

网页的 865 档案基线快照独立纳入源码，发布时离线检查各平台指纹。上游滚动变化不会阻止重新发布网站；旧基线和已批准的新目录互不覆盖。

## 安全、费用与限制

- 不自动刷机、改家庭网络、开启付费 runner 或自动充值。
- 使用账号现有私有 Actions 分钟与存储配额，不承诺无限免费。x86 最多并行两项，多型号及手动软件组合各最多并行四项，每项限制 45 分钟。多型号和组合诊断保留三天；不保存 QA 固件、密钥或密码。无变化只做索引检查。
- 只有独立批准任务使用该仓库短期 `GITHUB_TOKEN` 的 Contents 写权限。构建上游二进制的任务保持只读，不给它发布权限；未扩大网页令牌或 Connector 授权范围。
- 更新失败时主页标明失败并保留上次批准记录。原有可下载固件仍受 Artifacts 到期限制；保留批准记录不等于上游永久保留旧构建器或软件包。
- 成功的正常构建现在保留实际输入快照，可在断开上游网络后用原配置重建，详见 [归档说明](REBUILD.md)。这不是整个软件源或永久主机环境镜像，也不承诺成品逐字节复现。SHA256 可发现损坏或字节变化，不能独立保证第三方软件安全。
- 这六种引导回归不是所有软件组合、全部实体设备、USB/WWAN 硬件或真实代理线路的测试。
- GitHub 自身权限、配额不足或调度故障仍可中断任务。查看主页链接中的红色步骤和保留报告；不会通过改变账户收费或削弱权限自动绕过限制。

维护者可在私有仓库 Actions 中手动运行 `Automatically follow tested upstream`（x86）、`Automatically approve tested device updates`（多型号）、`Automatically approve tested box resources`（盒子）或 `Verify real device and software combinations`（扩展组合，不按日重复运行）。公开逐型号任务只保存无私人输入的检查报告。暂停可禁用对应工作流；不会因此删除历史批准或已有产物。多型号历史有 512 个版本上限，达到上限会停止批准，避免无限增长，不会自动删除历史。
