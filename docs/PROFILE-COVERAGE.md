# 逐型号云端编译覆盖

公开仓库的 `Compile every public device profile without personal data` 会对原站公开的 Kwrt 型号逐一生成固件并校验实际输出。使用临时 root/root、HTTPS、默认软件加 curl，不载入用户 Secrets、覆盖文件、私人配置或令牌；仅保存检查报告，不公开这些测试固件。

每批最多八个型号，同时运行最多十批。每个型号最多十五分钟，每批最多一百三十五分钟。失败保留原因，后续型号继续检查。若整批中断，保留已有报告，但不会把残缺批次提升为完整覆盖。

报告位于 `updates/profile-coverage.json`，记录目标、型号、软件组合、构建规则、构建器/软件源指纹、输出文件校验与运行链接。只有与当前验收目录一致的指纹，网页才显示此型号独立通过。规则或上游变更时旧报告继续保留，但不能冒充当前证据；失败项会重试，有效成功项可复用。

玩客云使用作者构建器的私有缓存，单独由私有网页联动测试覆盖；x86 有独立的虚拟机启动流程。盒子具体型号的内核和 DTB 采用独立资源验证和代表组合打包，不与主设备目录重复相加。

该任务每周检查，也可手动运行。使用 GitHub 标准托管 runner，不启用付费 runner 或自动充值。设备默认组合能通过，不代表所有用户自选组合都能通过；闪存容量、软件依赖和上游资源仍可能阻止构建。云端编译与文件校验不等于真实设备开机、无线射频、USB/WWAN 或 ESXi 验收。

2026-10-28 完整补测实际检查 863 个公开档案：841 个默认组合通过、22 个默认组合失败。R3D 的保留驱动修正另行通过；21 个 Rockchip 默认失败保留原缺包原因，其中五个 Radxa 及 Linkease EasePi R1 相同设备 ID 的官方 25.12.6 替代已实际编译完整镜像。玩客云原始软件源读取及实际烧录包也另行通过。不同来源和不同配置的成功不改写原默认组合失败；详情见 [RELEASE-14.md](RELEASE-14.md)。
